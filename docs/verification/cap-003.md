## 失败边界与一致性验证

- 代码未 bump、版本回退或非法 SemVer、缺失 base/完整 Git 历史均失败；纯文档无需 bump。实际临时 Git 仓库验证 merge-base、目标分支独有改动、删除、跨目录重命名和带空白路径。
- PR head / main 合并后 SHA 选择、完整 SHA tag、Chart 基准版本加 SHA 后缀、重跑版本稳定均通过单元验证；metadata 对实际 checkout 的比对及未提交源码拒绝通过测试。
- 已提取并执行 Workflow 实际门禁，前置 failure/skipped/cancelled 均不能进入发布；六条检查名、依赖关系和发布 Job 最小权限有契约回归检查。
- Registry mock 验证 HTTP 401/403/429/500 与网络错误不能被视为不存在，仅 manifest 404 可进入首次发布；架构/source/revision、内容 digest 不匹配失败。
- Docker image index 中仅选择 linux/amd64，忽略 attestation 的 unknown 架构项；已有匹配制品复用，部分镜像缺失时只补齐缺失项。以上为离线验证，未调用真实 GHCR 推送 API。
- Chart 打包使用临时副本，源文件及 kind/legacy values 字节保持不变；从真实打包文件读取并渲染，验证 API、前端、迁移和初始化容器镜像一致。未改变数据库 values 或保留策略。
- 镜像未完整发布或 Chart 推送后读回失败时，无成功 release.json；成功复用路径的发布清单包含完整制品身份，不含 token。
- 静态审查新增 Workflow/发布脚本未包含应用 Helm 安装、集群修改、Flux、E2E 或测试环境清理。install-helm 脚本仅安装本地工具。
