## Why

Lab 需要集中维护 Dell PowerEdge 物理机资产，统一记录设备标识、配置、位置和使用情况。当前仓库尚无应用，首版建立可在现有 kind 集群部署的资产台账，满足人工维护与查询需求。

## What Changes

- 提供物理机添加、编辑、删除、列表和详情，支持分页、关键词搜索及型号、使用状态筛选。
- 记录名称、唯一 Service Tag、型号、管理 IP、iDRAC 地址、实验室、机柜、U 位、硬件配置摘要、负责人、用途、状态和备注。
- 使用 Python 后端、PostgreSQL 数据库和 React 前端，提供数据库迁移、容器构建与本地 kind 部署说明。
- 全部面向用户的 UI 文案使用英文；文档可以使用中文，用户录入内容允许中文。
- 提供本地访问与数据库持久化方案，并将 README 与项目定位对齐。

首版默认方案：硬件使用摘要字段；删除采用确认后的永久删除；暂不包含登录、权限、操作审计或恢复功能，访问限定在本地开发环境。以上是对未决细节的提案默认值，不代表用户已单独确认。首版不连接 iDRAC、不存储其凭据，不包含自动采集、设备控制、批量导入导出和集群高可用。

## Capabilities

### New Capabilities

- `physical-server-inventory`: 物理机数据模型、CRUD API、校验、分页搜索筛选和英文管理界面。
- `local-kind-deployment`: 容器构建、镜像加载、现有 kind 集群部署、本地访问和 PostgreSQL 持久化。

### Modified Capabilities

无。当前没有已有规格需要修改。

## Impact

- 新增后端、前端、数据库迁移、容器和 Kubernetes 部署文件；实施阶段确定实际目录并更新 README。
- 新增物理机 REST API 与 PostgreSQL 表；当前无已有业务接口或数据迁移兼容负担。
- 使用现有 kind 集群，不重新创建或删除用户集群；实施时检查集群名称、上下文与存储条件。
- 本变更仅生成规划文档；后续实施需验证英文交互、数据库约束、完整 CRUD 流程和部署后数据保留。
